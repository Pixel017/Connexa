How it works

From link token to normalized data in four calls

STEP 01

Your end user links an account

Mint a link token, send the hosted browser flow. Out comes an account token scoped to one linked account in one category — the initial sync runs automatically.

requestPOST /api/link-tokens
Authorization: Bearer <data key>
STEP 02

Sync pulls provider data into Common Models

Idempotent and diff-aware: every run reports added / updated / unchanged, fires LinkedAccount.synced webhooks, and stamps the account's last sync time.

requestPOST /api/ticketing/v1/accounts/<token>/sync
STEP 03

Serve normalized data — or write it back

Discover the schema before writing; every row carries the raw provider payload in remote_data. Passthrough gets you to the provider's own API when you need it.

requestGET /api/ticketing/v1/tickets
X-Account-Token: <account token>
