Security & privacy

Built to be verified, not just believed

One platform holds your customers' credentials and business data. Here's exactly how it's protected today — and what's still on the roadmap. No badge without the audit behind it.

Scoped keys, not a master password

Every credential is a scoped API key — data, gateway, agent, admin — hashed at rest in production mode, maskable in logs, revocable from the console. Key creation and revocation are themselves audited events.

Audit trail on everything

Key changes, link tokens, account syncs, tool-access decisions — every meaningful action lands in one append-only trail, browsable live from the console.

HMAC-signed webhooks

Every delivery carries X-Connexa-Signature (sha256 over the raw body with your endpoint secret) plus the event type — verify before you trust.

Data-loss prevention for agents

SecurityRule runs on agent tool traffic: REDACT or BLOCK credit-card numbers, emails, secret tokens, or any regex you add — org-wide or per tool pack — before the tool executes.

Humans approve sensitive actions

Sensitive tool calls open an approval request instead of executing. A human approves or rejects it from the console; the decision is logged with actor and timestamp.

The strongest residency: your own disk

Connectexa is self-hostable by design — the SQLite volume sits in a container you run, on machines you control. Cloud postures can promise regions; self-hosting removes the question.
